# 尼康 Z6 固件 3.80 说明（摄影师版）

> 写于 2026-10-29
> 对象：`Z_6_0380.bin`（Z6 机身固件 v3.80）
> 说明：本文尽量不用术语。凡是带标记的判断，都在文末注明依据强度。

---

## 一、先说结论

1. **这份固件是真的。** 文件大小 33.31 MB，与尼康官方发布值吻合到小数点后两位，不是别人改过的包。
2. **3.80 是个很小的补丁。** 整套固件近 3400 万个字节，真正动过的只有"主控程序"里的几处，改动量小到可以精确数出来。
3. **它修的是 Exif 记录，不是画质。** 用 B 门或遥控 B 门拍长曝光时，快门速度值有时会被错误写进照片的 Exif 信息里。成像本身没受影响，是"元数据记错了"。
4. **如果你拍长曝光并且在意 Exif（比如做延时、做素材归档、交给客户看参数），这一版值得升。** 如果你从不用 B 门，升级带来的实际变化几乎为零。
5. **不要尝试自己做固件刷进去。** 相机有签名校验，改过的包刷不进去；强行操作的风险是变砖，只能返厂。

---

## 二、相机里到底装了什么

Z6 的固件不是一个巨大的程序，而是**四个独立的程序包**被打包在一个文件里。这次我们把它们拆开看了：

| 程序包 | 大小 | 通俗理解 | 它管什么 |
|---|---|---|---|
| **Engine**（`eg`） | 33.5 MB | 机身"大脑" | 拍摄流程、菜单、对焦、测光、图像处理、视频、文件写入、USB/无线、几乎所有你能在菜单里碰到的功能 |
| **VR**（`vr`） | 839 KB | 防抖"小脑" | 五轴机身防抖（IBIS）的实时控制，响应速度要求极高，所以单独跑 |
| **ExMCU**（`ex`） | 512 KB | 机身"神经末梢" | 电池、开关、快门动作、镜头供电、看门狗（死机自救）这些底层硬件动作 |
| **第二单片机**（`_tpj01`） | 57 KB | 另一个小协处理器 | 具体分工未公开，从体量看是辅助控制 |

打个比方：**Engine 是摄影师，VR 是 stabilization 的手，ExMCU 是神经反射**。
它们各跑各的，通过内部总线互相通报。

> ✅ 这四个包的名字、大小、顺序是从固件自己的目录表里读出来的，不是猜的。

## 三、相机跑的是什么系统

不是安卓，不是 Linux 桌面，也不是很多人猜的 VxWorks。

**是 µT-Kernel**——一个日本的实时操作系统（TRON 家族），在嵌入式设备里用得非常多。
它的特点正好符合相机需求：

- **开机快**：几秒内就能进可拍摄状态
- **响应确定**：按下快门到真正曝光，延迟是稳定的，不会因为后台在忙而抖动
- **体积小**：整个内核只占很小一块

主处理器是 **ARM926**。这是在固件里直接看到的（有一个专门负责 ARM926 核间通讯的模块）。

相机里还夹带了一段 **UEFI/EDK2** 的代码——就是电脑主板上那套固件框架的开源代码。
尼康用它来做 **NVMe（CFexpress 卡）驱动**。这也解释了尼康下载页为什么会写
"BSD License (NVM Express Driver)"——因为那段代码是 BSD 许可的开源件。

> ✅ µT-Kernel、ARM926、EDK2/NVMe 这三条都有固件内的字符串与模块名作证，不是推测。

## 四、3.80 这一版实际改了什么

### 官方说法

尼康原话（意译）：修复了在选择 **"Bulb（B 门）"** 或 **"Time（遥控 B 门）"** 进行长时间曝光时，
**快门速度值有时会被错误记录进 Exif 数据**的问题。

### 我们实测到的

- **四个程序包里，只有 Engine 变了。** VR、ExMCU、第二单片机这三个包，**一个字节都没动**。
- Engine 内部 **93.91% 的字节完全一样**，只有约 6% 不同。
- 这 6% 里，**绝大部分还不是真的改了**——是因为前面插入了几个字节，后面的代码整体往后挪了几字节，
  逐字节对比就会"看起来全都不同"。把挪动的量补回来之后，相同率是 **98.4%–99.6%**。
- 真正插入的字节，总共只有**几处、每处 2 个字节**，后面跟着一批"地址修正"（编译器搬家后要顺手改的跳转偏移）。

**换句话说：这不是重写，是真正的"小修补"。** 打个比方——
一本书改了一个标点，但因为排版重排，后面每一行的字都往后挪了一格；
你若逐行比对，会觉得"全变了"，实际上只改了一个标点。

> ✅ 以上数字都是从解密出来的固件上逐字节量出来的，可复现。

### 对拍照的影响

- **画质：没有任何变化。**
- **对焦、测光、防抖、连拍：没有任何变化**（对应模块逐字节相同）。
- **Exif 里的快门速度：** 用 B 门/遥控 B 门长曝光时，以前偶尔会记错，现在修正了。

## 五、从固件里能看出的功能结构

固件里保留了 163 个"源码文件名"（开发时的模块名）。这不是我们猜的架构图，是尼康自己写进去的。
下面按摄影师能理解的方式归类：

### 拍摄
- 拍摄主流程、连拍、释放状态控制、拍摄能力协商
- **快门控制**（`ShutterControl`）
- 对焦相关的镜头信息与镜头指令排序

### 防抖与镜头
- 机身防抖指令服务（启动、镜头信息、参数设置）
- 镜头通讯：供电、光圈、对焦驱动

### 图像与文件
- Exif/IPTC 写入：静态照片、视频、通用标签
- Picture Control
- DCF 目录管理（就是存储卡里的 `100NCZ_6` 那种文件夹规则）、目录编号、存储信息

### 存储
- SD 卡驱动
- **CFexpress / NVMe** 驱动（就是那套 UEFI 代码）
- Eye-Fi 卡支持（老无线 SD 卡，现在基本没人用了）

### 连接
- **PTP**（USB 联机拍摄、无线传图用的协议）
- **SnapBridge 那一套**（固件里叫 LifeShare）：蓝牙、蓝牙配对、Wi-Fi、传图列表
- Wi-Fi 驱动与网络接口

### 高级/自动化
- **间隔拍摄 / 自动拍摄脚本**（固件里叫 AutomaticOperation，有一整套脚本引擎和指令）
- 视频录制与播放
- 设置数据（相机设置、用户设置、菜单日志、重置）

### 系统底层
- µT-Kernel 封装层（任务、信号量、事件标志、互斥、系统时间）
- ARM926 核间通讯
- GPIO / I2C / UART / 定时器驱动
- 固件更新与校验（`FirmwareManagement`、`FirmwareChkLib`）

> 🔎 上表是按模块名归类，反映**代码组织方式**，不等同于尼康官方宣传的功能列表；
> 但每一项都能在固件里找到对应模块，不是凭印象写的。

## 六、几个有意思的小发现

1. **存储卡里会留日志文件。** 固件里有 `A:\AOLOG00.TXT`、`B:\AOLOG%02X.TXT` 这样的路径，
   A/B 对应两个卡槽。这是"自动拍摄（间隔/脚本）"的运行日志。用间隔拍摄出问题时，卡里可能能找到记录。

2. **固件自己会报三个模块的版本号。** 内部有一条日志格式 `Eg:… Ex:… Vr:…`，
   也就是机身主控、外接单片机、防抖模块各自的版本。菜单里只显示一个总版本，内部其实分三个。

3. **带了一整套 Wi-Fi 联盟认证测试代码。** `wfa_*` 那一组是 Wi-Fi Alliance 的测试工具代码，
   大概是做无线认证时随代码带进来的，正常运行时不参与拍摄，但确实占了一点空间。

4. **快门模式的名字是硬编码的字符串表。** `Err / Time / Bulb / Full / Card` 排在一起，
   B 门和遥控 B 门就来自这里——这也正是 3.80 修的那块区域附近。

> ✅ 这几条都是从解密后的字符串与代码里直接看到的。

## 七、目前情况：确定的和不确定的

### 已经确定 ✅

| 项目 | 状态 |
|---|---|
| 这份固件是否官方原件 | 是。大小与官方发布值吻合到小数点后两位 |
| 加密方式 | 已完全搞清，并且成功解密（用公开的先例方法 + 多个机型样本交叉验证） |
| 四个程序包的划分 | 已确认，含大小、顺序、校验（共 4 个模块校验和 1 个包校验全部通过） |
| 3.80 改了哪个包 | 只有 Engine，另外三个包逐字节相同 |
| 3.80 改了多少 | 几处 2 字节插入 + 地址修正，总长度不变 |
| 相机用的 RTOS | µT-Kernel |
| 主处理器 | ARM926 |

### 还没完全确定 ⚠️

1. **那几处 2 字节插入具体是哪条指令。** 位置已经锁定到很小一段，
   但那一小段正好落在反汇编工具没能自动识别成函数的空隙里；
   要补完需要一次"写操作"权限，本次会话被禁用，所以停在一步之遥。
   **这不影响上面的结论**——改动位置、改动量、改动性质都有两套独立证据。

2. **Exif 写入那段代码的精确逻辑。** 我们知道它属于哪几个模块、在哪个区域，
   但没有逐行读完——因为整块有 33.5 MB，反汇编工具需要分片跑。

3. **机身签名密钥。** 固件头部有一个用"逐机型 8 字节密钥"生成的签名。
   Z8/Z9 的已经被公开研究解出，**Z6/Z7 的还没有**。
   这意味着：**即使我们能改固件内容，也无法签出相机认得的包**——所以"自制固件"这条路目前是关着的。

### 明确做不到的

- **改机/越狱/加功能：做不到。** 签名校验过不去。
- **刷第三方固件：做不到。** 同上，而且风险是变砖。
- **从固件里"提取照片算法"：意义不大。** 图像处理部分没有独立成易于移植的形式。

## 八、给你的实际建议

| 你的情况 | 建议 |
|---|---|
| 常用 B 门 / 遥控 B 门长曝光，且在乎 Exif 记录 | **升级到 3.80**，这正是它修的东西 |
| 做延时、间隔拍摄，需要参数准确归档 | 升级 |
| 从不拍长曝光，机器运行正常 | 升不升都行，功能上没有其它变化 |
| 想通过改固件加功能 | 不可行，别试 |

**升级方法（官方流程）**：
把 `Z_6_0380.bin` 复制到存储卡**根目录**（不能放文件夹里）→ 插卡开机 →
菜单「设定菜单 → 固件版本 → 更新」→ 按屏幕提示操作。
**升级过程中绝对不能断电**，中断会导致机器无法开机，只能返厂。

> ⚠️ 另一个提醒：Z6 原厂电池是 EN-EL15/EN-EL15a/EN-EL15b 系列。
> 升级时电量请保持充足（建议 50% 以上），这不是危言耸听，而是变砖的主要原因之一。

## 九、这件事的意义在哪

对摄影师而言，这次分析最大的价值不是"破解了固件"，而是三件事：

1. **可以确认手上这份包没被动过手脚**，不用担心来源不明的"固件"。
2. **知道升级到底改了什么**——不是听官方一句话，而是能精确到"只动了主控里的几处"。
3. **知道相机出问题时该往哪儿想**：防抖异常 → VR 包；电池/开关/快门动作异常 → ExMCU 包；
   菜单/对焦/传图/文件异常 → Engine。三个包是独立的，故障域也是分开的。

至于"能不能自己改固件加功能"——答案是**目前不能**，而且不是技术不够，是签名这一关过不去。
这一点在可预见的将来不会变。
